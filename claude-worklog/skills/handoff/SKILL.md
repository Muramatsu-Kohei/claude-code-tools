# 前セッションからの引き継ぎ

現在のディレクトリの引き継ぎ内容(自動取得):

!`node C:/claude/ClaudeCode/claude-worklog/worklog.js handoff`

現在の状態:

- ブランチと未コミットの変更: !`git status --short --branch`
- 直近のコミット: !`git log --oneline -3`

## 手順

1. `ARGUMENTS` に名前が指定されている場合は、その引き継ぎを取り直す。指定が無ければ上の内容を
   そのまま使う。**同じリポジトリ内の別ツール**(注入テキストの「他に未完の作業があるツール」に
   並んでいたもの)なら位置引数、別リポジトリなら `--project` を使う。

   ```
   node C:/claude/ClaudeCode/claude-worklog/worklog.js handoff <ツール名>
   node C:/claude/ClaudeCode/claude-worklog/worklog.js handoff --project <プロジェクト名>
   ```

2. 引き継ぎが記録されていない場合は、その事実を伝えて終わる。**勝手に別の作業を始めないこと。**
   代わりに `worklog list --verbose` で直近の記録を見るという選択肢を示す。

3. 引き継ぎがある場合は、**現在の状態と食い違っていないか**を確認する。以下は特に確認する。
   - 引き継ぎが前提としているブランチと、今いるブランチが同じか
   - 引き継ぎに書かれたファイルが実際に存在するか
   - 「未コミットの変更が残っている」と書かれているなら、それが今も残っているか
   - 引き継ぎに書かれた時点より後に、別のセッションが同じ場所を変更していないか
     (`worklog list --verbose` で引き継ぎより新しいセッションがないか見る)

   食い違いがあれば**先に指摘する**。古い引き継ぎのまま作業を進めるのが一番危険。

4. 食い違いが無ければ、以下を簡潔に(5〜8 行で)提示する。
   - 引き継ぎの要点
   - 最初にやること(1 つだけ)
   - 判断が保留になっている点があれば、それをユーザーに問う

5. 調査・確認のような読み取りだけの作業は、そのまま進めてよい。
   ファイルの変更・コミットなど元に戻しにくい操作に入る前には、ユーザーの合図を待つ。
