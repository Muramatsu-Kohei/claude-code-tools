# セッションの終了手続き

作業を切り上げる前の締め作業をまとめて行います。**下の手順を順番どおりに実行**してください。
各手順は「該当する変更が無ければスキップして次へ」進みます。何をスキップしたかは最後に報告します。

現在の状態(自動取得):

- ブランチと未コミットの変更: !`git status --short --branch`
- 直近のコミット: !`git log --oneline -5`
- 変更規模: !`git diff --stat HEAD`

## 手順 1: 変更内容の把握

上の状態を確認し、必要なら `git diff` で中身を見て、このセッションで何を変えたかを把握します。
git リポジトリでない場合は手順 4 を飛ばし、それ以外は通常どおり進めます。

## 手順 2: ドキュメントへの反映

**今回の変更によって、プロジェクトの記述が古くなっていないかを確認し、必要なら加筆・修正します。**
これは忘れやすく後から効いてくるため、コミットより前に行います。対象の例:

- `README.md` — 機能の追加・削除、セットアップ手順、前提条件、使い方、オプション一覧
- `docs/` 配下の文書 — 仕様・設計・運用手順
- `TODO.md` / `CHANGELOG.md` 等 — 完了した項目、新たに判明した課題
- コード内のファイル冒頭コメントや設定サンプル — 実装と食い違っていないか

判断基準は「**この変更を知らない人がドキュメントだけを読んだとき、誤解するか**」です。誤解するなら直します。
一方で、内部的な小さなリファクタリングなど、外から見た振る舞いが変わっていない場合は何も書きません。
体裁を整えるだけの無意味な更新はしないこと。

## 手順 3: 検証

テスト・ビルド・リンタが定義されていれば実行します。定義が無ければ、変更したスクリプトの構文チェックや
実際の起動確認など、その場で可能な範囲の確認を行います。
**失敗した場合はそこで止めて報告します。**失敗を隠してコミットに進んではいけません。

## 手順 4: コミット

- 検証が通ったことを確認してからコミットします。
- 論理的にまとまった単位で分けます。無関係な変更を 1 つのコミットに混ぜないこと。
- コミットメッセージは既存の履歴の言語・書式に合わせ、何を・なぜ変えたかが分かるように書きます。
- **`push` は行いません。**`reset --hard`・force push・履歴改変も行いません。
- `main` / `master` で直接作業している場合は、コミット前にその旨を伝え、ブランチを作るべきか確認します。

## 手順 5: 記憶(memory)の更新

このセッションで得た知見のうち、**今後のセッションでも役に立ち、かつコードや git 履歴を読めば
分かる類のものではないもの**があれば記憶に保存します。判断が難しければ保存しません。

- 該当するもの: ユーザーの好み・方針、環境固有の落とし穴、外部リソースの場所、この先の計画
- 該当しないもの: コードの構造、今回直したバグの内容、CLAUDE.md に既に書かれていること

**該当が無ければ何もしない**のが正常です。毎回書き足すと索引が使えなくなります。

## 手順 6: 作業ログへの記録

以下を整理して `worklog` に記録します。

- **一言要約**: 何をしたか。40〜60 文字程度。成果物と変更対象が分かる具体的な表現にする。
- **やったこと**: 完了した作業を 1 行ずつ。後から見て意味が分かる粒度にまとめる。
- **更新した文書**: 手順 2 で加筆・修正した文書とその要点。無ければ省く。
- **次にやること**: 未完了の作業・残った課題。無ければ省く。
- **次回の始め方**: 次のセッションがこの続きを再開するための具体的な指示。ここが最も重要で、
  次のセッションの冒頭に自動で渡されます。以下を必ず含めます。
  - 最初に手を付けるべきこと(1 行目に置く)
  - 対象ファイルの絶対パス
  - 実行して状態を確認すべきコマンド
  - 判断が保留になっている点、決めていない選択肢
  - 未コミットの変更が残っている場合はその旨

```
node C:/claude/ClaudeCode/claude-worklog/worklog.js add --via finish \
  --summary "<一言要約>" \
  --done "<やったこと1>" --done "<やったこと2>" \
  --doc "<更新した文書と要点>" \
  --next "<次にやること>" \
  --handoff "<次回の始め方 1行目>" --handoff "<2行目>" --handoff "<3行目>"
```

- `--done` `--next` `--doc` `--handoff` は繰り返し指定できる。`--handoff` は指定順に改行で連結される。
- セッション ID は環境変数から自動で解決されるので `--session` は不要。
- 値に改行を含めてはいけない。改行が必要なら項目を分ける。
- **値にバックティック(`` ` ``)と `$` を使わないこと。** PowerShell ではバックティックが
  エスケープ文字として解釈され(`` `n `` が改行になるなど)文字列が壊れる。bash でも
  二重引用符内のバックティックはコマンド置換になる。コマンド名やパスを引き継ぎ文に書くときは
  引用符で囲まず素のまま書く。
- 上記が避けられない複雑な文面を渡したい場合は `--handoff-stdin` を使い、標準入力から流し込む。

## 手順 7: 報告

最後に以下を簡潔に(10 行程度で)まとめて表示します。

1. 実施した内容とスキップした手順(スキップの理由を一言)
2. 作成したコミット
3. **次回の始め方**(記録したものをそのまま提示。ユーザーがここだけ読んで状況を把握できるように)

なお、記録した「次回の始め方」は、次に同じディレクトリで新しいセッションを開いたときに
SessionStart フックが自動でコンテキストへ渡します。手で貼り直す必要はありません。

$ARGUMENTS
