# スコープ(1リポジトリの中のツール単位)の使い方

`claude-worklog` の「1リポジトリの中のツール単位」の説明。実装仕様は [scope-spec.md](scope-spec.md)。

---

## 何が変わるか

いま困っているのは次の2点。

1. `ClaudeCode` の親で開くか `claude-worklog` の子で開くかで、**記録が別プロジェクトに分かれる**
2. `claude-statusline` を触りたいのに、**`claude-worklog` の引き継ぎが注入される**

変更後はこうなる。

| | 変更前 | 変更後 |
| --- | --- | --- |
| プロジェクトの単位 | ディレクトリ | **git リポジトリ**(親でも子でも同じ) |
| ツール単位の記録 | なし | **あり**(変更ファイルから自動で判定) |
| 引き継ぎ | プロジェクトに1本 | **ツールごと**。他ツールの未完は1行の索引で見える |

---

## 親で開くか、子で開くか

**どちらでも記録は同じ場所に溜まる。**分裂しなくなるので、作業内容で選べばよい。

| | 子で起動(`claude-worklog\`) | 親で起動(`ClaudeCode\`) |
| --- | --- | --- |
| 引き継ぎの注入 | **そのツールの分が全文で出る** | 最新1本 + 他ツールは1行の索引 |
| 親 README・LICENSE 方針・ツール横断の変更 | cwd の外になり扱いにくい | **やりやすい** |
| 記録の場所 | 同じ | 同じ |

- **1つのツールを作る・直す** → 子で起動。cwd からツールが確定するので注入が最も正確
- **リポジトリ全体の作業**(親 README の一覧表、LICENSE の方針統一、横断リファクタ) → 親で起動
- 途中で横断作業になったら親で開き直せばよい。記録は同じ場所に続く

**注意:** `claude --resume` の候補はディレクトリ単位(Claude Code 側の仕様)。子で始めた
セッションは親から `--resume` しても候補に出ない。worklog の記録は統合されるが、
会話の再開だけはディレクトリを合わせる必要がある。

## 新しいセッションで注入されるもの

```
## 次回の始め方 (claude-worklog / 07/30 14:02 のセッションからの引き継ぎ)
まず worklog today --days 7 を叩き、~ 印の件数を数える。
作業ツリーは clean。main から 8 コミット、push なし。

他に未完の作業があるツール:
  claude-statusline (07/28)  WSL 手順の追記が途中
  claude-window-keeper (07/25)  常駐時の CPU 使用率の確認待ち
別のツールを触るなら /handoff <ツール名> で切り替える。

## 直近の作業ログ (claude-worklog)
- 07/30 14:02 [main] claude-worklog: 短縮ラッパーを同梱し README を整備 (8 commit, 13 files)
```

- **全文は1本だけ。**全ツール分を入れると「無関係な引き継ぎ」が増えるだけなので入れない
- 索引は最大3件、14日以内のものだけ
- 未完のツールが無ければ索引は出ない
- 最後の1行があるので、Claude 自身が必要に応じて切り替えられる

---

## コマンド

```
worklog list --scope claude-worklog      # そのツールの記録だけ
worklog handoff claude-statusline        # そのツールの引き継ぎに切り替える
worklog today --days 7                   # ClaudeCode/claude-worklog の形で表示
/handoff claude-statusline               # スキルからも同じことができる
```

## スコープが有効になる条件

**リポジトリごとに自動判定する。**「自分の README / LICENSE / package.json を持つ最上位
ディレクトリが2つ以上あるか」で決まる。実際のリポジトリで確認した結果。

| リポジトリ | 判定 | 中身 |
| --- | --- | --- |
| repo-A | 有効(7) | `tool-a` … `tool-b` |
| repo-B | 有効(7) | `tool-a` … |
| ClaudeCode | 有効(3) | `claude-statusline` `claude-window-keeper` `claude-worklog` |
| repo-F | **無効**(0) | `UI` `Widgets` `Tests` `docs` … → 内部構造なのでツールではない |
| repo-E | **無効**(1) | `fmt-a` のみ |

1リポジトリ1ツールでは無効になり、**今と完全に同じ挙動**になる。`UI` や `docs` が
ツール名として出てくることはない。

### ツールが増えたとき

**自動で有効に切り替わる。**判定は毎回行う。

さらに、スコープは記録に焼き付けず**表示のたびに計算する**設計にした。判定材料
(変更ファイル一覧)は最初から全レコードに保存されているため、**過去のセッションにも
遡ってラベルが付く。**

repo-E を例にすると、いまは `fmt-a` だけが README を持つので無効。2つ目のツールに README を
置いた時点で有効になり、それまでに `fmt-a` を触ったセッションも `[fmt-a]` として表示される。
記録の作り直しは不要。

判定式を後で改良したときも、履歴全体の分類がその場で直る。

## 設定

`~/.claude/worklog/config.json` に追加されるもの。

| キー | 既定 | 意味 |
| --- | --- | --- |
| `scopeMode` | `auto` | `off` で機能ごと停止、`on` で自動判定を無視して常に有効 |
| `scopeIndexMax` | `3` | 索引に出す他ツールの最大件数 |
| `scopeIndexMaxAgeDays` | `14` | これより古い未完は索引に出さない |

---

## 限界

- ツールの判定は「変更ファイルが最も多いディレクトリ」という目安。同梱の外部ライブラリを
  大量に触った回などに、的外れなラベルが付くことがある。**表示が変わるだけで、引き継ぎが
  消えることはない**
- ツールディレクトリを削除・改名すると、過去セッションのラベルが変わる(記録は残る)
- 明示したいときは `/wrap` `/finish` に `--scope <名前>` を渡す。人が指定したものを常に優先する
